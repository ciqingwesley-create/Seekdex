# “蜘蛛 / 玻璃杯”本地诊断

验证日期：2026-10-07。Windows，Intel i7-8700；Chinese-CLIP ViT-B/16，PyTorch CPU、OpenVINO CPU。

## 结论与边界

用户反馈“现在似乎都好了”。本次当前图库也未复现“玻璃杯排出蜘蛛、蜘蛛搜索找不到蜘蛛”的反常现象，**不能确定原先异常的根因**。未发现缺少 eval、随机文本向量、检索符号 / 排序错误或抽样向量错位的证据。

没有删除、重建或写入用户的 AI 索引，没有修改 model_id、模型权重或应用预处理。没有下载替代模型，也没有全盘遍历。所有数据库诊断均针对用户数据库的本地副本；照片仅在本机读取。原异常样本及当时筛选条件未获得，因此当前正常样本不能替代历史异常的复现。

本次仅加了诊断辅助函数和回归测试，并修正 Top-K 边界同分时任意选取部分候选的问题，改为按 file_uid 稳定取舍。这个同分细节**不是已证实的语义异常根因**。

## 1. 文本确定性

“蜘蛛、玻璃杯、一只蜘蛛、一个玻璃杯、猫、咖啡杯”每个连续编码 20 次，共保存 120 个 512 维向量。

- 每个文本的 20 次向量逐元素相同，最大绝对差值为 **0**。
- 同一文本归一化向量的余弦相似度为 **1**（float32 点积可能出现约 1e-7 的舍入误差，另用 float64 重归一化复核）。
- 主模型和文本模型 training 均为 False，无处于训练模式的 dropout。
- 加载明确调用 `.eval()`；文本推理位于 `torch.inference_mode()`。
- 文本取 Chinese-CLIP 的 BERT CLS，再应用文本投影，检索入口执行 L2 归一化。
- 使用固定本地 Chinese-CLIP 模型的 tokenizer；本次 29 个查询与官方 tokenizer 的完整 52 位 token 序列一致。
- “蜘蛛”连续 20 次 Top-20 的 UID、顺序与分数完全一致。

## 4. 官方实现对照

使用 [Chinese-CLIP 官方实现](https://github.com/OFA-Sys/Chinese-CLIP) 的 cn-clip 1.6.0：`load_from_name("ViT-B-16")`、eval、官方 preprocess / tokenize / encode_image / encode_text、两边 L2 normalize。直接矩阵点积检索，未使用应用搜索层。

为遵守“不下载大型新模型”，将现有固定 Hugging Face safetensors 权重按官方布局转换到本地临时 checkpoint，Q/K/V 拼接、投影转置，官方严格加载接受全部参数。没有下载另一份 checkpoint。官方 loader 会先将部分权重转成 float16，再在 CPU 转回 float32，这也会引入少量数值差异。

| 对照 | 结果 |
| --- | ---: |
| 官方文本 vs 应用文本：最低余弦 | 0.99999970 |
| OpenVINO CPU vs 应用 PyTorch 图片：最低余弦 | 0.99999988 |
| 官方编码器使用应用相同像素 vs 应用图片：最低余弦 | 0.99999964 |
| OpenVINO vs PyTorch：最大图文 cosine 差值 | 0.0000002384 |
| 官方相同像素 vs 应用：最大图文 cosine 差值 | 0.00019333 |
| 官方原生预处理 vs 应用：最大图文 cosine 差值 | 0.04911789 |

发现实际预处理差异：官方示例直接将全图缩放到 224×224；应用先限制到 448，再由 Hugging Face 处理器按短边缩放并中心裁剪。部分构图的分数和排序因此不同。相同像素的控制组没有发现编码器语义空间不兼容。**本次保留现有预处理和 embedding**。

官方和应用的小样本“蜘蛛”首位都是蜘蛛，“玻璃杯”首位都是真正玻璃杯，未复现原异常。但这不表示模型所有查询都正确：例如“一个透明玻璃杯”在两种实现中均将一张金属茶杯放在首位。不能假设增加提示词一定改善结果。

完整逐查询排序及控制组保存在 `.verification/semantic/official-comparison.json`。
